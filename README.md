# Streamer Moderator Simulator

A cozy, portrait-first **Godot 4** game about moderating a livestream chat in
real time. You are the moderator of a small VTuber stream; chat scrolls, you
decide what stays.

Play it in a browser: **<https://infoe-labs.github.io/mod-simulator/>**
(see [Deploying](#deploying)).

## The game

Chat messages arrive continuously. Each one gets exactly one of three
decisions:

| Key | Button | Meaning |
|-----|--------|---------|
| `1` | **ALLOW** | keep it in chat |
| `2` | **DELETE** | hide it, no strike |
| `3` | **BAN** | remove the user |

You tap a row to focus it, then tap a decision (or use the number keys on a
desktop). Harmless messages are automatically allowed when their timer runs out,
with the same score, combo and meter rewards as clicking ALLOW. Abuse still needs
your intervention. Accepted messages remain in a bounded, scrolling chat history.

Desktop has a separate moderation log with the last 30 outcomes. On phones,
feedback appears over the video for ten seconds, can be dismissed, and leaves the
chat and action buttons accessible. Automatic harmless accepts update the log
quietly. Tapping a row never moderates it, so a scrolling thumb cannot ban
somebody by accident.

Two meters decide the run:

* **Mood** (streamer happiness) — falls when something hurtful survives or a
  good message is punished, rises with correct calls and combos.
* **Trust** (your relationship with the streamer) — built by consistency,
  wrecked by banning regulars and letting harassment through.

A run lasts about four minutes and moves through five phases (warm-up, growing
chat, busy stream, viral moment, final wave). Spam repeats, harassers come back
with alt accounts, and borderline messages make you think.

* **Win** — reach full mood with enough trust, and the streamer invites you on
  a date.
* **Lose** — mood hits zero and the streamer ends the broadcast because it got
  too upsetting.

Everything is fictional. Offline chat combines procedural conversation grammar
(shared topics, replies, emotes and everyday chatter) with 169 authored moderation
examples. A run seed reproduces the conversation and streamer appearance.

### Two ways to get a chat

| | **Classic Mode** | **AI Chat Mode** |
|---|---|---|
| where the messages come from | procedural conversations + authored moderation examples | a small language model running **in your browser** |
| needs | nothing | a one-time, opt-in model download (106–705 MB) |
| offline | yes | yes, once the model is cached |
| scoring, categories, win condition | identical | identical |

AI chat is completely optional and off by default. Whatever the model says has
to pass the same validation and moderation policy as an authored line, and when
the model is slow, weak or unavailable the authored chat takes over in the same
frame — the header chip tells you which one you are reading, and so does the
results screen. [docs/AI.md](docs/AI.md) covers the runtimes, the model
catalog, measured speeds on real hardware, and the honest list of limitations.

### Modes

All three modes are unlocked for everyone from the first launch. Nothing is
locked behind progress or payment; difficulty unlocks are kept only as a stat
in the save file.

* **Tonight's Stream** — the standard run.
* **Relaxed** — slower chat, gentler penalties, a good place to learn the ropes.
* **Viral Night** — the busy end of the curve.

### Look

A low-poly desk scene with a laptop, and a VTuber built procedurally from
Godot primitives (a fresh appearance each run, reproducible from its seed, configured in
`game/data/`, no external models). The chat, meters and buttons are ordinary
Godot 2D `Control` nodes drawn over the 3D feed: readable text and honest
touch targets rather than text baked into a 3D screen.

## Requirements

* **Godot 4.7.2 stable** with matching **Web export templates**
  (single-threaded build).
* **Python 3** for the asset generators, palette gate and local server.
* **Node.js** only for the optional Playwright browser check and for refreshing
  the vendored AI runtimes (`tools/ai/vendor.sh`).

No backend, no accounts, no analytics and no paid API. Nothing is fetched to
play the game: icons and all 14 sounds are generated by the scripts in `tools/`,
and the whole game ships as static files.

The optional **AI Chat Mode** adds one thing, and it is opt-in: a language model
(`@mlc-ai/web-llm` on WebGPU, `@wllama/wllama` on CPU) whose *code* is vendored
into this repository, and whose *weights* the player explicitly agrees to
download once from Hugging Face. Inference happens in Web Workers on the
player's device; no text ever leaves it. See [docs/AI.md](docs/AI.md).

## Running it locally

```bash
# one-time import (also generates game/.godot/)
godot --headless --path game --import

# run the game in a window
godot --path game
```

In a browser (Godot web builds need cross-origin isolation headers, which
`tools/serve.py` sends):

```bash
./tools/export.sh                      # writes dist/
python3 tools/serve.py --port 8000     # then open http://127.0.0.1:8000/
```

`tools/serve.py` sets `Cross-Origin-Opener-Policy`/`Cross-Origin-Embedder-Policy`,
`Cache-Control: no-store`, and the `application/wasm` MIME type. If your browser
complains about SharedArrayBuffer, that is the single-threaded build being extra
strict — restart the server, hard-refresh (Ctrl/Cmd-Shift-R) and it will load.

The AI subsystem is already vendored in `game/web/ai/vendor/`, so nothing has to
be installed to play or to run the tests. To refresh it, or to keep the weights
on your own server:

```bash
tools/ai/vendor.sh                        # re-copy npm runtimes into game/web/ai/vendor
tools/ai/fetch_models.sh --list           # what could be self-hosted
tools/ai/fetch_models.sh smollm2-135m-cpu # ~106 MB, served from ai/models/
```

./tools/check_all.sh          # everything below, plus the browser pass
SKIP_BROWSER=1 tools/check_all.sh   # engine and python gates only

| `... -s res://tests/layout_audit.gd` | chat tray never collapses, rows have real size and opacity, decision buttons on screen and thumb-sized, popups and the speech bubble never collapse to one character per line, **label contrast measured against the background actually painted** |
| `... -s res://tests/mobile_ui.gd` | menu, settings, tutorial steps, results, ending choices and pause overlay at narrow/short/landscape sizes; real touch swipes and wheel input; no horizontal overflow; bottom controls reachable |
| `... -s res://tests/pause_input.gd` | the pause overlay is on top, processes while paused, keeps every button visible, focusable and thumb-sized, and each button's signal is wired to its effect |
| `... -s res://tests/ai_tests.gd` | the AI contract without a model: schema validation, category/policy clamps, the safety floor that re-scores abuse disguised as a compliment, queue bounds, banned identities, fallback when no bridge exists, honesty of the chat-source label, and that Classic Mode is still bit-identical with the AI code in the loop |
| `python3 tools/check_palette.py` | theme palette: WCAG contrast, font-size floors, 44 CSS px touch targets on a 390 pt phone |
| `node tools/e2e/e2e.mjs --url ...` | boots the exported web build in Chromium (iPhone 12 profile, SwiftShader), walks all thirteen screens, asserts zero console errors and `200`s for every asset — including the vendored AI runtime — and drives one run through a stubbed `window.ModSimAIMock` to prove model-written chat reaches the tray, that the honesty chip changes, and that the authored chat still fills in when the model is slow |
| `node tools/e2e/ai_lab.mjs --url ... --model <id>` | **real inference**: loads a model in the page and requires the output to be valid JSON with real categories, distinct lines, no links, no refusals, a working classification, a valid reaction mood, reported throughput, and not one request to a third-party CDN |
| `python3 tools/check_shots.py` | reads the screenshots back and fails on blank frames: chat ink present, 3D feed rendered, ALLOW/DELETE/BAN drawn in their accent colours |

The browser pass, if you want to run it on its own:

```bash
cd tools/e2e && npm install
python3 -m pip install -r tools/requirements.txt   # Pillow, for the screenshot gate
node e2e.mjs --url http://127.0.0.1:8000/
node e2e.mjs --small-phone --url http://127.0.0.1:8000/   # 320 × 568 CSS px
python3 tools/check_shots.py        # from the repo root

# and the slow one, which actually downloads a model and runs it:
python3 tools/serve.py --dir game/web --port 8766 --coi &
node tools/e2e/ai_lab.mjs --url http://127.0.0.1:8766/ --model smollm2-135m-cpu
```

Or let the main gate run it: `AI_LAB=1 tools/check_all.sh`.

## Controls and accessibility

* Portrait-first, 720 × 1280 reference canvas, scaled with the window; safe-area
  insets are respected so the tray clears a phone notch or home bar.
* Tap targets are ≥ 44 CSS px on a 390 pt phone (enforced by the palette gate).
* No hover-only interaction. Nothing needs a keyboard.
* Desktop: `1`/`2`/`3` for ALLOW/DELETE/BAN, `Esc` or `P` to pause, `Tab` to move
  focus, `Enter` to activate.
* Colour is never the only signal: rows carry a badge and category chips
  (`NEW`, `TRUSTED`, `REPEAT`, the moderation category), and every decision
  pops a written verdict rather than a coloured flash alone.
* Settings: master volume, music and sound-effect sliders, mute everything,
  vibration on supported devices, and a **Reduce motion / low detail** toggle.
  There is also an erase-local-data button (double-tap to confirm) and a note
  if browser storage is unavailable, e.g. in private browsing.
* The 3D feed picks its own detail level from the device when the run starts
  (`_detect_quality()`); on the lowest tier the desk render and screen flash
  are dropped and the streamer feed simplifies, so older phones keep a smooth
  chat.

## PWA and offline

The web preset enables the service worker, icons, standalone display and an
offline page (`game/web/offline.html`). After the first load the game runs with
the network off, with two caveats that belong to browsers rather than to this
game:

* iOS Safari can evict the cache (and `localStorage`) after extended absence, so
  a long-unused install may re-download and start from an empty save.
* Save data is per-origin `localStorage`. Clearing site data clears your best
  scores and settings.

If you turned AI chat on, the model weights are cached by the runtime itself
(Cache API), separately from the game's own service worker: the game stays
playable offline either way, and without the weights it simply uses the
authored chat.

**Android (Chrome):** open the URL → menu → *Add to Home screen* / *Install
app*. It launches standalone.

**iOS (Safari):** Share → *Add to Home Screen*. It opens on the title screen;
the first tap you make (tapping *Start*) is the gesture Safari requires before
it lets the page play sound, so music and clicks begin from that moment.

## Layout of the repo

```
game/                 Godot project
  data/               balance.json, messages.json (169 lines, 14 categories)
  src/core/           simulation: sim, scoring, difficulty, catalog, save
  src/ai/             browser-LLM chat: bridge, validator + policy, queue/fallback
  src/screens/        menu, title, tutorial, game, results, ending, settings
  src/ui/             theme, widget factory, chat row, AI status row
  src/world/          desk scene, procedural VTuber, stage
  tests/              the suites listed above
  themes/warm_cozy.json   single source of truth for colours, font sizes, metrics
  web/offline.html    offline page copied into dist/
  web/ai/             the JavaScript AI subsystem + vendored runtimes (docs/AI.md)
  web/ai-lab.html     isolated proof page for real inference
tools/                export, serve, asset generators, gates, e2e driver
  ai/                 vendor.sh (npm runtimes), fetch_models.sh (self-hosting)
docs/AI.md            runtimes, model catalog, measured performance, limits
```

Gameplay simulation (`src/core/`) never touches rendering: `Sim` is a plain
`RefCounted` state machine driven by `tick(delta)`, which is what lets the
balance harness replay thousands of runs headlessly.

Regenerate the generated assets any time:

```bash
python3 tools/make_icons.py
python3 tools/make_audio.py
```

## Deploying

`.github/workflows/deploy.yml` installs Godot 4.7.2 plus matching export
templates, runs every gate, exports `dist/` and publishes it to GitHub Pages.

1. Push this repository to GitHub.
2. **Settings → Pages → Source: GitHub Actions**.
3. Push to `main` (or run the workflow manually). The URL appears in the
   workflow's deploy step.

The build uses relative asset URLs, so it works from a project subpath like
`https://you.github.io/mod-simulator/` as well as from a site root. GitHub Pages
does not send COOP/COEP headers; that is fine here because the export is the
single-threaded build (`variant/thread_support=false`) and
`ensure_cross_origin_isolation_headers=false`.

The same is true of the AI subsystem: without COOP/COEP the CPU runtime cannot
use `SharedArrayBuffer`, so it runs single-threaded and slower (measured in
[docs/AI.md](docs/AI.md)). Nothing breaks — the game keeps serving the authored
chat and says so. If you host the build somewhere you control, sending those two
headers makes CPU inference about five times faster, and
`tools/ai/fetch_models.sh` lets you ship the weights with the build so players
never hit Hugging Face at all.
